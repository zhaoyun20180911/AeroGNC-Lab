## 软件总览 / Overview

AeroSys Lab 是使用 C++20 与原生 Win32/GDI 构建的航天器制导、导航与控制（GNC）及动力学仿真平台。软件把参考任务生成、闭环控制、执行机构、动力学传播、扰动注入、实时可视化和结果导出放在同一个桌面程序中，并允许用户在中文或英文单语界面之间即时切换。

| 顶层模块 | 主要任务 | 典型控制与执行机构 | 主要输出 |
| --- | --- | --- | --- |
| 卫星姿轨控 | 对地定向、惯性定向、目标跟踪、姿态机动与轨道保持 | PD/PID/LQR、反作用飞轮、三轴微推力器 | 姿态/角速度误差、飞轮状态、轨道六状态误差、推力与推进剂 |
| 火箭上升入轨 | 六组固定发射场—目标轨道任务的两级闭环上升 | 轨迹外环、姿态内环、TVC、滚转 RCS | 实际/标称轨迹、姿态、质量、级段、入轨位置与速度误差 |
| 火箭一级回收 | 从一级分离到 RTLS 安全着陆的全阶段仿真 | 阶段制导、在线凸 QP、发动机、TVC、RCS、栅格舵 | 阶段、预测落点、着陆误差、剩余推进剂、执行机构与求解器指标 |

## 卫星姿轨控 / Satellite GNC

### 姿态参考与姿态控制

卫星模块支持四类任务：

- **对地定向**：依据瞬时轨道位置和速度构造 LVLH/轨道参考姿态，使星体随轨道运动持续指向地球。
- **惯性定向**：保持用户给定的惯性空间姿态，不随轨道坐标系旋转。
- **目标跟踪**：由地面目标经纬度和卫星位置构造视线方向，连续生成跟踪参考姿态。
- **姿态机动**：在指定机动时间内通过四元数最短路径插值生成平滑参考姿态和参考角速度。

实际姿态以标量在前的四元数 `q_BI` 表示，含义为从星体系主动旋转到 ECI；角速度在星体系表达。控制器用实际姿态与参考姿态形成姿态误差，再由 PD、带抗积分饱和的 PID 或 LQR 生成三轴控制力矩。执行机构为三只正交反作用飞轮，仿真考虑飞轮惯量、最大力矩和最大转速，因此能够看到控制器输出、执行机构饱和与星体响应之间的闭环关系。

### 轨道保持与推进剂消耗

标称轨道和实际轨道由各自状态独立传播。轨控首先在 RTN/LVLH 轨道坐标系中计算位置、速度六状态误差，再生成惯性系修正加速度：

```text
a_cmd = g(r_nom) - g(r_actual)
        - Kp · (r_actual - r_nom)
        - Kd · (v_actual - v_nom)
```

其中重力差补偿抵消标称位置与实际位置处的中心引力差，`Kp` 决定位置偏差的恢复强度，`Kd` 抑制相对速度和超调。修正加速度乘以卫星当前质量得到期望推力，经过推力上限和位置/速度死区处理后，再从 ECI 转换到星体系形成三轴微推力器指令。死区内不点火，用于避免微小测量或数值误差导致推力器频繁启停。

推进剂消耗按 `ṁ = T / (Isp·g0)` 计算，推进剂质量属于卫星湿质量，因此消耗后总质量会同步下降；推进剂耗尽后轨控推力被切断。姿态环与轨道环彼此独立，轨控推力只改变平动，反作用飞轮只改变转动。模块还支持连续、脉冲、正弦和确定性随机力矩扰动，以及一次性 RTN/LVLH 速度脉冲。当前 J2、大气阻力、日月三体和太阳光压选项是后续扩展接口，尚未进入主动力学。详见[卫星模型](docs/satellite_model.md)。

## 火箭上升入轨 / Launch to Orbit

### 固定任务与标称轨迹

上升模块内置三处发射场与两类目标圆轨道的组合，共六组任务：

- 文昌、西昌、Cape Canaveral；
- 300 km / 28.5° 与 500 km / 51.6° 目标圆轨道。

每组任务的标称轨迹从 `data/rocket_missions` 中读取，并嵌入正式发布的 EXE。位置、速度和连续标量使用线性插值，姿态使用四元数 SLERP，级段等离散量保持离散切换。标称数据只作为参考，实际火箭状态不会被“吸附”或重置到标称轨迹。

### 闭环制导与两级动力学

实际状态在 ECI 中独立传播。轨迹外环根据位置和速度误差生成受限的期望推力方向，姿态内环再用 PD/PID/LQR 跟踪参考姿态，并将控制量分配给发动机推力矢量控制（TVC）和滚转 RCS。动力学包含球形地球引力、随姿态与 TVC 变化的推力、相对旋转大气的阻力、推进剂流量、时变质量和惯量、一级分离以及级间状态连续交接。

用户可以改变实际火箭的初始偏差、质量、惯量、推力、比冲、阻力系数、大气密度和 TVC 偏置，用来观察闭环制导的纠偏能力。每一级分别管理推进剂、关机条件和有限的燃烧时间延长；任务文件结束后，标称和实际状态分别进入两体滑行，不会在结果页伪造入轨收敛。入轨快照给出最终位置、速度和轨道参数误差。详见[火箭上升与任务数据](docs/rocket_model.md)。

## 火箭一级回收 / First-Stage Recovery

### 默认交接状态与阶段流程

回收模块从一级分离交接状态开始。默认演示工况约为 NED 坐标 `N = 20 km`、`E = 0`、高度 `80 km`，北向速度 `600 m/s`、Down 轴速度 `-50 m/s`（仍在上升），一级总质量 `90 t`、可用回收推进剂 `62 t`，等效发动机组最大推力 `2.28 MN`。

```text
分离 → 翻转 → 返场点火 → 滑行 → 再入点火
     → 栅格舵气动下降 → 动态着陆点火 → 在线凸 QP 着陆 → TOUCHDOWN
```

任务状态机根据时间、距离、高度、速度、剩余推进剂和发动机状态切换阶段；每个阶段使用适合当前目标的制导逻辑，而不是用一套固定增益覆盖全程。回收全局交接量以 ECEF 保存，靠近着陆场后的平动制导使用以着陆点为原点的 NED 坐标，姿态仍以四元数传播。

### 制导、优化与执行机构

返场和再入阶段控制横向回程、能量消耗与落点收敛；气动下降阶段使用四片栅格舵修正预测落点；着陆阶段按照当前高度和下降速度动态判断点火时机。Landing 阶段采用滚动时域凸二次规划：每个制导周期根据最新状态重新构造问题、求解未来一段时间的推力序列，只执行第一个控制量，然后在下一周期重新规划。若求解异常或超时，系统切换到有边界保护的启发式安全控制，并记录回退状态。

控制分配器把制导指令转换为发动机开关与节流、TVC、姿控 RCS 和栅格舵偏角，同时执行限幅、速率限制和可用性约束。界面实时显示当前阶段、实际轨迹、目标着陆点、预测落点、位置/速度/质量/推进剂、推力、TVC、四片栅格舵以及 QP 成功率和耗时。V1 为 Falcon-9-like 教学与工程仿真，并不使用或声称使用真实私有飞控参数；模型边界见[一级回收 V1 实现报告](AeroSys_Lab_Recovery_V1_Implementation_Report.md)。

## 坐标系、动力学与单位

| 参考系 | 本项目中的用途 | 定义 |
| --- | --- | --- |
| ECI | 卫星轨道与火箭上升的全局位置、速度和姿态 | 地心惯性系；地球中心为原点，坐标轴在惯性空间中保持固定 |
| ECEF | 一级回收的全球位置、速度与着陆场交接 | 地心地固系；随地球自转 |
| RTN / LVLH | 卫星轨道误差、轨控指令和轨道扰动 | R 径向向外，T 沿轨道速度方向，N 为轨道面法向；LVLH 用于构造随轨道旋转的局部参考 |
| NED | 一级回收着陆场附近的局部平动与制导 | 原点在着陆点，三轴分别指向北、东、地心方向（Down 为正） |
| Body | 姿态动力学与执行机构 | 随飞行器转动的星体系/箭体系，力矩、角速度和执行机构指令主要在此表达 |

仿真内核统一使用 SI 单位，界面仅在显示和输入层进行 km、t、deg 等单位换算。姿态统一使用四元数以避免欧拉角奇异，固定步长仿真与播放速度分离：改变播放倍率只改变每帧推进的仿真步数，不改变动力学步长和控制器离散周期。完整约定见[坐标、姿态与单位约定](docs/conventions.md)。

## 控制器与执行机构

| 对象 | 控制误差 | 控制方法 | 执行机构 |
| --- | --- | --- | --- |
| 卫星姿态 | 四元数姿态误差、角速度误差 | PD / PID / LQR | 三轴反作用飞轮 |
| 卫星轨道 | RTN/LVLH 位置与速度六状态误差 | 含重力差补偿、死区和限幅的 PD | 三轴微推力器 |
| 火箭上升 | ECI 位置/速度误差与姿态/角速度误差 | 轨迹外环 + 姿态内环 | 主发动机、TVC、滚转 RCS |
| 一级回收 | 落点、位置、速度、姿态及约束余量 | 分阶段制导 + Landing 滚动时域凸 QP | 发动机节流、TVC、RCS、栅格舵 |

PID 的抗积分饱和用于避免执行机构达到力矩上限后积分项继续累积。项目使用积分限幅和饱和处理，使执行机构恢复可用时不会因过大的历史积分量产生明显反向冲击。默认增益依据飞行器惯量、执行机构控制权限和目标闭环响应尺度生成；自定义模式允许分别修改 X/Y/Z 轴的 PD、PID 或 LQR 参数。详见[控制、轨控与扰动](docs/control_and_disturbance.md)。

## 界面、交互与数据

- 顶部语言开关在中文和英文之间切换，任一时刻只显示一种语言。

## 从源码运行 / Run from Source

环境要求：

- Windows 10/11 x64；
- CMake 3.24 或更高版本；
- Visual Studio 2022 C++ 工具链；
- 构建过程无需第三方运行时库，Release 使用静态 MSVC 运行库。

最简单的方式是双击根目录中的 `运行 AeroSysLab.bat`。脚本会启动现有的 `build/Release/AeroSysLab.exe`；若文件不存在，则先配置并编译 Release 版本。

也可在 PowerShell 中执行：

```powershell
cmake -S . -B build -A x64
cmake --build build --config Release --parallel
ctest --test-dir build -C Release --output-on-failure
./build/Release/AeroSysLab.exe
```

双击 `构建并测试.bat` 可完成 Release 编译与测试；双击 `生成便携版.bat` 可生成本地便携包。也可运行：

powershell -ExecutionPolicy Bypass -File scripts/package_portable.ps1
